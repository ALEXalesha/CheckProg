# CheckProg 2.0: переход с Tkinter на Qt (PySide6)

Дата: 2026-09-19. Предыдущая версия 1.3.1 (Tkinter).

## Зачем

В Tk на Windows каждый виджет это отдельное системное окно без двойной буферизации, поэтому ресайз дёргается (см. `2026-09-19-resize-performance.md`). Qt рисует окно одним буфером и перерисовывает только видимые строки списка. Заодно уходят самодельные меню (`flatmenu.py`) и ручной перенос комментариев.

## Решения

- **Вид:** стиль Qt `windows11` (на Windows 10 Qt сам откатывается на `windowsvista`). Светлая и тёмная тема через `QStyleHints.setColorScheme()`: «как в системе» это `Qt.ColorScheme.Unknown`, светлая `Light`, тёмная `Dark`. Qt сам следует за Windows и сам красит заголовок окна.
- **Список:** `QListView` + `ChecklistModel(QAbstractListModel)` + `ItemDelegate`. Одна строка на пункт, раскрытый комментарий рисуется внутри той же строки, высоту считает делегат.
- **Окружение:** `.venv` в папке проекта. Глобальный Python не используется.
- **Сборка:** PyInstaller `--onedir`. Portable zip (папка + `portable.flag`) и установщик Inno Setup, как раньше.
- **Версия:** 2.0.0.
- **Подсказка внизу окна** убрана. Её текст переезжает в «Справка» → «Как пользоваться» и во всплывающую подсказку списка.

## Модули

| Файл | Что делает | От чего зависит |
|---|---|---|
| `model.py` | без изменений | stdlib |
| `settings.py` | без изменений | stdlib |
| `theme.py` | `MODES`, `MODE_LABELS`, `normalize_mode`, `apply_mode(app, mode)`, `is_dark(app)` | PySide6 |
| `listmodel.py` | `ChecklistModel`: единственный, кто меняет `Checklist` после загрузки | model, PySide6 |
| `delegate.py` | `ItemDelegate`: `paint`, `sizeHint`, `hit(option, index, pos)` → `"check"`, `"arrow"`, `"text"`, `"note"` или `None`; редактор текста пункта | PySide6 |
| `window.py` | `MainWindow`: меню, список, панель комментария, поле добавления, файлы, клавиши | всё выше |
| `app.py` | `main()`: DPI, `QApplication`, стиль, `MainWindow` | window |

`flatmenu.py` удаляется. Из `theme.py` удаляются палитры Tk, чтение реестра и DWM-заголовок: это теперь делает Qt.

### ChecklistModel

- Роли: `DisplayRole` = текст, `CheckStateRole` = done, `NoteRole`, `ExpandedRole`.
- Методы: `set_checklist(cl)`, `add(text) -> row|None`, `toggle(row)`, `rename(row, text) -> bool`, `set_note(row, text) -> bool`, `set_expanded(row, bool) -> bool`, `expand_all(bool) -> bool`, `remove(row)`, `move(src, dst) -> dst`.
- Каждое изменение шлёт точные сигналы Qt: `dataChanged` для одной строки, `beginMoveRows`/`endMoveRows`, `beginRemoveRows`/`endRemoveRows`, `beginInsertRows`/`endInsertRows`, `modelReset` при смене списка. Раскрытие шлёт `dataChanged` с ролью `SizeHintRole`, и вид пересчитывает высоту строки.
- Сигнал `changed` после любого изменения. Окно по нему обновляет заголовок, `*` и счётчик «Выполнено».
- Перетаскивание: `flags` содержат `ItemIsDragEnabled`, `supportedDropActions() = MoveAction`, `moveRows` перемещает через `Checklist.move`. Внешние данные не принимаются.

### ItemDelegate

- Строка: слева квадратик (рисуется через `QStyle.PE_IndicatorItemViewItemCheck`, чтобы совпадать со стилем), затем текст пункта в одну строку с многоточием при нехватке места, справа стрелка ▼/▲ у пунктов с комментарием. Выполненный пункт серый и зачёркнутый.
- Раскрытый комментарий под текстом: курсив на 1 pt мельче, цвет `PlaceholderText` палитры, перенос по словам через `QTextLayout`/`QFontMetrics.boundingRect(... TextWordWrap)`, слова длиннее строки переносятся по символам (`TextWrapAnywhere`).
- `sizeHint` зависит от ширины вида и раскрытости. Кэш по `(note, width)`.
- `hit()` возвращает зону по тем же прямоугольникам, что использует `paint()`. Отрисовка и попадание щелчка считаются одной функцией `_layout(option, index)`, чтобы не разойтись.
- Редактор: `QLineEdit` поверх текста пункта. Enter сохраняет через `ChecklistModel.rename`, Esc отменяет, пустой текст оставляет старый.

## Поведение (как в 1.3.1)

- Щелчок по квадратику или пробел отмечает. Щелчок по стрелке, → и ← раскрывают и сворачивают комментарий.
- Двойной щелчок по тексту или F2 открывают правку. Двойной щелчок по комментарию переводит фокус в панель комментария.
- Повторный щелчок по выделенной строке, щелчок по пустому месту или Esc снимают выделение.
- Перетаскивание строки и Ctrl+↑/Ctrl+↓ переставляют пункты. Выделение едет вместе с пунктом.
- Delete удаляет без подтверждения. Выделение переходит на соседний пункт.
- Контекстное меню по правой кнопке, Shift+F10 и клавише меню: Отметить, Изменить, Комментарий, Удалить, Выше, Ниже.
- Панель комментария под списком привязана к объекту `Item`, а не к номеру строки. Каждое изменение текста сразу пишется в пункт. Без выделения панель выключена. Отмена Ctrl+Z не переходит между пунктами.
- Меню: «Файл» (Создать Ctrl+N, Открыть Ctrl+O, Сохранить Ctrl+S, Сохранить как Ctrl+Shift+S, Выход), «Пункт», «Вид» (три режима темы, Развернуть/Свернуть все комментарии), «Справка» (Как пользоваться, О программе). Мнемоники `&Файл`, `&Пункт`, `&Вид`, `&Справка`.
- Горячие клавиши работают и в русской, и в английской раскладке. Ctrl+буква Qt на Windows сопоставляет по виртуальной клавише. Alt+Ф/П/В/С в английской раскладке (Alt+A/G/D/C) окно открывает само через `nativeVirtualKey()`.
- Файлы: `*` в заголовке при несохранённых изменениях. Вопрос «Сохранить изменения?» при закрытии, создании и открытии другого файла. Последний файл открывается при запуске и запоминается в настройках. Путь из командной строки открывается вместо последнего. Ошибки чтения показываются, текущий список не теряется.
- Тема запоминается в `settings.json` под тем же ключом `theme`.

## Сборка и окружение

- `requirements.txt`: `PySide6-Essentials>=6.8`. `requirements-dev.txt`: `-r requirements.txt`, `pytest`, `pytest-qt`, `pyinstaller`, `pillow`.
- `build.ps1`: создаёт `.venv`, если нет, ставит `requirements-dev.txt`, гоняет `pytest`, собирает `--onedir --windowed` с исключением ненужных модулей Qt, кладёт в `dist\CheckProg\`, делает zip и установщик.
- `installer.iss`: ставит всю папку `CheckProg\*` рекурсивно.
- `.venv/` в `.gitignore`.

## Тесты

- pytest + pytest-qt, `QT_QPA_PLATFORM=offscreen` для тестов окна, чтобы ничего не появлялось на экране. Реальные диалоги запрещены фикстурой, как сейчас.
- `test_model.py`, `test_settings.py` без изменений. `test_theme.py` переписывается под Qt.
- `test_listmodel.py`: каждое изменение шлёт правильные сигналы (`QAbstractItemModelTester` + `qtbot.waitSignal`), `dirty` и раскрытость как в модели.
- `test_delegate.py`: зоны `hit()` не пересекаются и покрывают строку, стрелка только у пунктов с комментарием, высота растёт при раскрытии и уменьшается при расширении окна, строки комментария не шире колонки.
- `test_window*.py`: сценарии из старых тестов окна (добавление, отметка, правка, удаление, перестановка, перетаскивание, панель комментария, файлы, тема, клавиши в обеих раскладках) и случайные последовательности действий с проверкой инвариантов после каждого шага.
- `test_perf.py`: 200 пунктов, все комментарии раскрыты, 100 шагов ресайза. Среднее время шага меньше 16 мс.

### Инварианты

1. Строки вида совпадают с `Checklist.items` по порядку, тексту, отметке и раскрытости.
2. Заголовок окна и счётчик всегда соответствуют `Checklist` (`*` равно `dirty`).
3. Панель комментария показывает комментарий выделенного пункта и пишет только в тот `Item`, из которого загружена.
4. Раскрытие и сворачивание не меняют `dirty`.
5. Выделение всегда указывает на существующую строку или его нет.
6. Зоны `hit()` совпадают с тем, что нарисовано.

## Что не переносится

- Ручной перенос комментариев и таймер переноса из 1.3.1: высоту строк считает Qt.
- `test_app_resize.py`: заменяется `test_perf.py` и тестами делегата.
