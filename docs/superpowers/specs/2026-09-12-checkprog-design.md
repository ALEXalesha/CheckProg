# CheckProg: дизайн

Дата: 2026-09-12

## Цель

Настольная программа для Windows: чек-лист, где можно вписать названия предметов и отмечать галочкой выполненные. Поставляется в двух вариантах: portable (запуск без установки) и setup (обычный установщик). К ней прилагается документация для пользователя.

## Функции

- Добавить пункт: поле ввода внизу окна, кнопка «Добавить» или Enter. Пустой текст и текст из одних пробелов не добавляются, края строки обрезаются.
- Отметить пункт: клик по колонке с галочкой или пробел на выделенной строке.
- Изменить текст: двойной клик по тексту или F2, правка прямо в строке. Enter сохраняет, Esc отменяет. Если стереть текст целиком, пункт остаётся со старым текстом.
- Удалить пункт: клавиша Delete или пункт контекстного меню.
- Поменять порядок: перетащить строку мышью. Также Ctrl+↑ и Ctrl+↓.
- Прогресс: строка «Выполнено: X из Y» и полоса прогресса.
- Меню «Файл»: Создать (Ctrl+N), Открыть (Ctrl+O), Сохранить (Ctrl+S), Сохранить как (Ctrl+Shift+S), Выход.
- При запуске открывается последний файл, если он ещё существует. Иначе создаётся пустой безымянный список.
- Путь к файлу можно передать аргументом командной строки. Так работает открытие через «Открыть с помощью».

## Сохранение и файлы

Работа устроена как в текстовом редакторе. Если есть несохранённые изменения, в заголовке окна стоит `*`. Перед «Создать», «Открыть» и закрытием окна программа спрашивает: «Сохранить / Не сохранять / Отмена».

Формат файла `*.json`, кодировка UTF-8, кириллица пишется как есть:

```json
{
  "version": 1,
  "items": [
    {"text": "Купить молоко", "done": false},
    {"text": "Позвонить в банк", "done": true}
  ]
}
```

Запись атомарная: сначала во временный файл в той же папке, затем `os.replace`. Если файл повреждён, программа показывает сообщение, а текущий список остаётся открытым. Повреждённым считается файл с неверным JSON, без `items`, с `items` не того типа или с пунктами без строкового `text`. Если у пункта нет `done`, он считается невыполненным.

## Настройки (последний открытый файл)

- Portable: рядом с `CheckProg.exe` лежит файл-маркер `portable.flag`. Тогда настройки пишутся в `settings.json` рядом с exe, а папка по умолчанию для списков — `lists\` рядом с exe.
- Установленная версия (маркера нет): настройки в `%APPDATA%\CheckProg\settings.json`, папка списков по умолчанию `Документы\CheckProg`.
- Если настройки не читаются или не пишутся, программа работает дальше без них и не падает.

## Архитектура

```
checkprog/
  __init__.py      версия
  __main__.py      запуск через python -m checkprog
  model.py         Checklist: пункты, операции, счётчик, load/save, флаг изменений. Без tkinter.
  settings.py      пути (portable или установленная), чтение и запись настроек
  app.py           окно на tkinter/ttk: Treeview, меню, горячие клавиши, диалоги
tests/
  test_model.py
  test_settings.py
packaging/
  launcher.py      точка входа для PyInstaller (onefile, без консоли)
  installer.iss    Inno Setup
  build.ps1        тесты, затем сборка portable zip и setup.exe
README.md          документация для пользователя
```

Модель — единственный источник истины. UI после каждой операции перерисовывает Treeview из модели и не хранит собственного состояния пунктов.

## Упаковка

- `packaging\build.ps1` запускает тесты, затем PyInstaller собирает `dist\CheckProg.exe`. После этого скрипт собирает `dist\CheckProg-Portable.zip` (exe и `portable.flag`), а если найден ISCC, ещё и `dist\CheckProg-Setup.exe`.
- Установщик: установка в Program Files, ярлык в меню «Пуск», ярлык на рабочем столе по желанию, удаление через «Приложения». Языки: русский и английский.

## Тестирование

Unit-тесты на `unittest` для модели и настроек. Инварианты, которые проверяют тесты:

1. `done_count <= total`, прогресс в диапазоне 0..1, для пустого списка 0.
2. Сохранение и загрузка дают тот же список, включая кириллицу, кавычки и эмодзи.
3. Любая изменяющая операция ставит флаг изменений, сохранение и загрузка его снимают.
4. `move` сохраняет набор пунктов (переставляет, но не теряет и не дублирует). Выход индекса за границы не ломает список.
5. Неудачное сохранение не портит существующий файл.
6. Некорректный файл вызывает понятную ошибку, модель остаётся прежней.

UI проверяется вручную по сценарию из плана.
